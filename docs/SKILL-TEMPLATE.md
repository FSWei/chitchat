# 插件与 Skill 怎么分工

很多人问："人设、说话风格这些内容，是不是应该塞进插件目录？" 不是。它们放 skill，插件只负责**执行**。

## 分工

| 层 | 放什么 | 生效方式 | 谁改 |
|---|---|---|---|
| **插件（本仓库）** | 确定性规则：切分、去重、禁词、注入格式、模式开关 | 每一轮都跑，不依赖模型是否记得 | 改代码 |
| **Skill** | 风格指南、语气示例、场景口径、人设设定 | 被加载时才进上下文（**软约束**） | 改 Markdown |
| **Provider 文件** | 会变的状态：情绪、人设摘要、昨日摘要 | 由插件每轮读取并注入 | 随时改文件 |

一句话：**硬约束写插件，软约束写 skill，会变的状态写文件。**

## 为什么风格指南不写进代码

1. 改一句话要发版、重启，成本太高；skill 改完下一轮就生效。
2. 风格是"模型该怎么做"，属于提示词；切分是"输出必须长什么样"，属于代码。混在一起两边都难维护。
3. skill 可以被别的宿主读（Claude Code、DSH 都读 Markdown），插件不行。

## 一个最小 skill 骨架

```markdown
---
name: my-chat-style
description: 我在 IM 里的说话风格（软约束，配合 chitchat 插件使用）
---

## 语气
- 短句，一条消息一个意思
- 不用"首先/其次/总之"这类书面连接词

## 禁止
- 不复述用户刚说过的话
- 不在闲聊里用列表和标题（插件会剥离，但别依赖它兜底）

## 场景
- 用户明显在忙 → 一句话说完
- 用户在倾诉 → 先接住情绪，不给方案
```

把它放在宿主能加载 skill 的目录，`chitchat` 插件负责执行层（气泡、长度、禁词），skill 负责"说什么、怎么说"。

## 想让插件读 skill 里的内容？

不用读。两条路：

1. **注入**：把要用的段落放进 `providers.mood` / `providers.persona` 指向的文件，插件每轮注入（有长度上限）。
2. **不注入**：让模型自己 `skill_view` 加载——但要注意这属于软约束，模型可能不加载；需要强约束就写进插件配置。

## 反面例子

- ❌ 把整份人设写进 `config.json` → 配置膨胀、改一次要热加载、还容易泄进公开仓库
- ❌ 在插件里硬编码 skill 名字 → 换个人用就报错
- ✅ `skill_guard.skills` 用配置传名单，默认空
