# 分层总览

> 这一页写的是**模式**，不是某个具体角色。本仓实现其中「说话 / 约束」两块，生活与世界两块给了脚本，其余给方法。

## 八块

| 块 | 职责 | 谁写 | 换掉它会怎样 |
|---|---|---|---|
| 身份 | 她是谁、长什么样、说话习惯 | 人设文本（skill / 角色卡） | 换一个人，其他块不动 |
| 生活 | 她怎么过日子：日记、日常、连载 | 定时任务 + 水位脚本 | 她只剩「今天」，没有前情 |
| 世界 | 她撞见什么：新闻、天气 | 抓取脚本 + 真实天气 | 日子向内收，全是我和猫 |
| 形象 | 照片：从日记状态生成提示词 | 提示词模板 + 出图服务 | 图和日子对不上 |
| 记忆 | 记得什么、忘什么 | 3 天 → 14 天 → 永久 | 要么爆上下文，要么记不住 |
| 说话 | 几条、多长、什么格式、怎么装配上下文 | 代码 + 配置 | 一次吐一整篇 |
| 调度 | 谁替她跑：定时任务、任务书、水位 | 宿主 cron | 她不动，日子停住 |
| 约束 | 白名单、写闸、TTL、失败放行 | 代码 + 配置 | 她在不该说话的窗口说话 |

**为什么这么切**：把「人设」直接写进系统提示词，会遇到三个必然问题。

1. **规则和身份混在一起**：想改一句说话习惯，得重写整段人设。
2. **记忆没有生命周期**：要么全塞上下文（爆 token），要么全靠检索（找不到「三天前那种感觉」）。
3. **输出形态不可控**：「请简短」是建议，不是约束，模型该长还是长。

分层之后每一块有独立的写者和判断标准，换掉一块不影响其余七块。

## 记忆：三层生命周期

模仿人脑巩固，但比向量库朴素得多：

| 层 | 保留期 | 内容 | 谁读 |
|---|---|---|---|
| 中期 | 3 天 | 原文：对话摘要、每日生活记录 | 模型每轮可读 |
| 长期 | 14 天 | 蒸馏后的场景式记忆：真实事件、情感锚点、承诺 | 模型可读 |
| 档案 | 永久 | 全部原文 | **模型不读**，只给人回看 |

关键设计：**蒸馏只复制、不删原文**。原文永不丢，模型只看提炼版 —— 既不爆上下文，也不会把细节永久丢失。

两路输入通常来自定时任务：

- 对话摘要：每 N 小时把新消息总结成一段
- 生活记录：每次只写「已经过完的那一段」，见 [LIFE.md](LIFE.md)

## 注入：顺序 + 预算

注入块不是拼得越多越好。一个可用的默认顺序：

1. 本轮待办清单（用户问了几个问题）
2. 当前时间（含时区，防止把「计划」讲成「已发生」）
3. 情绪 / 人设摘要（决定语气）
4. 记忆召回（带强触发条件，没命中就不查）
5. 模式（语言、语音、工作/闲聊）
6. 输出约束（放最后，最容易被遵守）

每条都要有**字符上限**。经验值：单段 600–800 字，总量控制在上下文窗口的一小部分；超了截断，不要全塞。

代码位置：`chitchat/context.py::build_injection`。

## 调度与状态

- 定时任务负责：摘要、生活记录、归档、蒸馏。
- 状态用文件（flag / json）：肉眼可查、可手改、可被别的进程读。
- 每个状态文件都要有 TTL，否则「忘记关闭」会变成永久故障。

`chitchat/modes.py` 里两个 flag 就是这套做法：`work.flag`（12 小时过期）、`chat-ok.flag`（10 分钟一次性凭证）。

## 治理

| 风险 | 手段 |
|---|---|
| 角色在正式工作窗口乱说话 | 输出窗口白名单（只有指定会话生效） |
| 读了不该读的内容 | 读取范围配置 + 只提炼话题级摘要 |
| 模型误改状态文件 | 工具调用前拦截，需要一次性批准 |
| 上下文被污染 | 后台线程不注入、不改写 |
| 记忆被灌进不该去的地方 | 新内容开新文件，不塞进旧链路 |
