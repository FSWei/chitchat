# 人格化 agent 的运行时

> 这一页写的是**模式**，不是某个具体角色。chitchat 只实现其中两层，其余层给出落地方式。

## 为什么要分层

把"人设"直接写进系统提示词，会遇到三个必然问题：

1. **规则和身份混在一起**：想改一句说话习惯，得重写整段人设
2. **记忆没有生命周期**：要么全塞上下文（爆 token），要么全靠检索（找不到"三天前那种感觉"）
3. **输出形态不可控**："请简短"是建议，不是约束，模型该长还是长

分层之后每一层有独立的写者和判断标准：

```
身份 identity      谁在说话（稳定，很少改）
行为 behavior      什么场景怎么应对（可迭代，按纠正记录长出来）
记忆 memory        记得什么、忘什么（有生命周期）
注入 injection     每轮塞什么进上下文（有顺序和预算）
表达 rendering     最终长什么样（确定性代码）
```

## 记忆：三层生命周期

模仿人脑巩固，但比"向量库"朴素得多：

| 层 | 保留期 | 内容 | 谁读 |
|---|---|---|---|
| 中期 | 3 天 | 原文：对话摘要、每日生活记录 | 模型每轮可读 |
| 长期 | 14 天 | 蒸馏后的场景式记忆：真实事件、情感锚点、承诺 | 模型可读 |
| 档案 | 永久 | 全部原文 | **模型不读**，只给人回看 |

关键设计：**蒸馏只复制不删原文**。原文永不丢，模型只看提炼版——这样既不爆上下文，也不会把细节永久丢失。

两路输入通常来自定时任务：

- 对话摘要：每 N 小时把新消息总结成一段
- 生活记录：每天生成"它这一天"，供后续对话引用（时间、天气、做了什么）

## 注入：顺序 + 预算

注入块不是拼得越多越好。一个可用的默认顺序：

1. 本轮待办清单（用户问了几个问题）
2. 当前时间（含时区，防止把"计划"讲成"已发生"）
3. 情绪 / 人设摘要（决定语气）
4. 记忆召回（带强触发条件，没命中就不查）
5. 模式（语言、语音、工作/闲聊）
6. 输出约束（最后一条，最容易被遵守）

每条都要有**字符上限**。经验值：单段 600–800 字，总量控制在上下文窗口的一小部分；超了截断而不是全塞。

## 行为：规则是长出来的

行为规则应该是**按纠正记录迭代**的文档，不是一次性写好的 prompt：

```markdown
## 不要连环提问（2026-xx-xx 用户纠正）
一次最多一个问题；更好的做法是少问多说。
```

每条规则带日期和触发原因，才能判断它是否还成立。规则文档属于 skill 层（可被多个宿主读取），不属于代码。

## 表达：确定性兜底

模型再听话也会输出文档格式。表达层用确定性代码兜底：

- 结构化内容（代码块、表格、附件）整条放行
- 其余按换行切、按句打包、超量合并尾部（不丢内容）
- 失败一律放行原文——**表达层不允许吞消息**

## 调度与状态

- 定时任务负责：摘要、生活记录、归档、蒸馏
- 状态用文件（flag / json）：肉眼可查、可手改、可被别的进程读
- 每个状态文件都要有 TTL，否则"忘记关闭"会变成永久故障

## 治理

| 风险 | 手段 |
|---|---|
| 角色在正式工作窗口乱说话 | 输出窗口白名单（只有指定 chat 生效） |
| 读了不该读的内容 | 读取范围配置 + 只提炼话题级摘要 |
| 模型误改状态文件 | 工具调用前拦截，需要一次性批准 |
| 上下文被污染 | 后台复盘线程不注入、不改写 |
