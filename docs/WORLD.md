# 她撞见的世界：新闻与天气

## 为什么需要这一块

只靠「公寓 + 猫 + 工作」写日记，日子会向内收：每天都一样，写的都是回音。外部世界给的是**撞见**——她刷到一条新闻，跟她今天在干的事撞上了，才有得说。

## 新闻：只取标题，观点自己写

`life/news_fetch.py` 只干一件事：把今天世界上发生了什么拉回来，**不写观点**。观点留给写日记的那一轮，而且只写 0 或 1 条。

```bash
python3 life/news_fetch.py fetch      # 抓今天（当天已缓存就直接输出）
python3 life/news_fetch.py fetch --force
python3 life/news_fetch.py list       # 只读缓存
```

### 源

| 源 | 地址 | 状态 |
|---|---|---|
| NPR | `feeds.npr.org/1001/rss.xml` | 可用，偶发 SSL 超时（脚本已重试一次） |
| Politico | `rss.politico.com/politics-news.xml` | 可用 |
| HN | `hnrss.org/frontpage` | 可用 |
| The Verge | `www.theverge.com/rss/index.xml` | 可用 |
| Ars Technica | `feeds.arstechnica.com/arstechnica/index` | 可用 |
| Wired | `www.wired.com/feed/rss` | 可用 |
| IT之家 | `www.ithome.com/rss/` | 可用 |

国内网络实测过：BBC、NYT、Al Jazeera、Washington Post、Google News 全部超时；TechCrunch 返回 403；TechNode 的 feed 有 12MB 且含未闭合 CDATA，解析失败。换源之前先在目标网络里跑一遍。

### 抓取规则

- 每个源最多 6 条，单次读取上限 2.5MB，超时 10 秒，失败重试一次。
- **去重**：标题归一化（去掉非词字符、转小写、取前 40 字）后相同的只留一条 —— 同一条新闻经常被几个源同时推。
- **按天缓存**：按角色时区的日期存 `news/YYYY-MM-DD.json`，同一天不重复抓。缓存里带 `errors`，哪个源挂了能看见。
- **取样**：每个源先取两条，再轮流补足到 14 条，避免一个大源刷屏。
- **失败降级**：某个源挂了就少几条，绝不因为没新闻让日记停摆；一个源都没抓到就输出 `NO_NEWS`。

### 输出长什么样

```
DATE=2026-11-24 共 14 条（只挑你有话想说的，0 或 1 条）
[NPR] ...
[HN] ...
[IT之家] ...
```

### 纪律：0 或 1 条

这是这一块最容易退化成的样子：**每天开一个「今日时政」栏目，硬凑一段平衡分析。** 一旦变成栏目，它就和「气象台账」是同一个病 —— 每天都必须有，于是每天都在编。

任务书里必须写死：

- **0 或 1 条，不强制**。没有撞上她今天的生活，就不写。
- 写的角度是「**从生活里撞见**」：刷手机看到、写代码卡住时瞄到，1–3 句带自己的利害，不许开小标题。
- 给正例和反例各一条，比讲道理有用。

## 天气：真实数据，只准一句

天气不是装饰，它决定三件事：她今天出不出门、照片的光线对不对、她说的话有没有方向。

- **取数**：用宿主提供的联网工具查角色所在城市的真实天气（当前有几个时间段，就看哪些）。
- **写进正文一句**：放在段首，例如「外头九度，云一层没开」。
- **禁止**：预报、逐小时数据、「预报写 X、实测 Y」、任何对账、任何概率。

为什么要禁：对账看起来「严谨」，实际是把日记变成账本。天气是背景，不是 KPI。一旦允许对账，第二天就会出现「我昨天说九度，实际八度」这种自我惩罚式段落，然后越写越长。

## 已知缺口

1. **天气没有脚本**：目前靠宿主工具现查，没有可复现的取数代码。要接自己的数据源，建议补一个 `life/weather.py`，输出固定格式一行（温度 / 天况 / 风 / 湿度），别让模型自由发挥。
2. **日记没有天气字段**：新格式把天气写进叙事句子后，照片模块原先读的 `**天气**` 头部字段就没有了。出图前必须显式规定天气从哪来（补一个字段，或从段首句解析），见 [IMAGE.md](IMAGE.md)。
